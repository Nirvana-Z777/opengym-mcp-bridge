## v1.4.5 数据口径

上游固定提交为 [2d70e026](https://github.com/DuarteSantos8/openGym/tree/2d70e026effc6602f513555166a97443520f0572)。Bridge 的 MIT 实现独立编写。隔离验收从外部 AGPL checkout 调用官方 MCP 只读处理器和官方前端模块。Bridge 运行镜像仅包含 Bridge 代码。

- 距离 `distance_m` 的单位为米，循环总时长和各轮时间为秒。弹力带的阻力标签来自当前器材目录，kg 值保留为标称阻力，容量仍为外部重量 × 次数。节奏格式依原记录返回。
- v1.4.5 肩部拆分及背阔肌新键用于新目录。旧历史快照有自己的显式口径，旧肩部和上背合并口径留在原坐标。对当前目录使用与上游一致的两项附加腰背映射。备份中的历史、器材、未知字段和原生同步标记保持原值。
- 今日计划使用用户明确给定的 IANA 时区。休息日直接返回，失效或歧义安排返回 `needs_choice`，可用 `routine_ids` 选定计划。组合训练按计划顺序保留动作位置和 ID。
- 开练目标目前支持普通次数及计时模板、手动目标和可验证的直线增重。涉及已运行周期、器材专用进阶、自动热身坡道、复杂循环安排或停滞减重的开练推导提示使用原 App。训练报告保留模板、实际开练目标和实绩，计划后来改动不会更改已保存的快照。
- 正式组计数排除热身，嵌套左右次数组只计一行且任一侧完成即记为完成。左右计时各计一行。每个动作计划内完成数封顶后计算总体完成率，额外组单独报告。未做动作保留在报告中，原生历史只写有完成内容的动作项。
- 体重原生读数存于每日行 `ins`，每日权重读取配置 `bwDaily` 的 first、avg 或 last，默认 first。称重输入显式 kg/lb，预览显示换算后的账户单位。围度按原生项目存 cm，输入可用 cm/in。已有同一时间或同一围度项目的不同数值标为冲突，整批等待重新预览。
- 建议是训练记录辅助。数据不足、口径变化、报告疼痛或恢复偏低时，不生成增加目标的操作。只有选择有效建议后才生成独立的 `preview_plan_change` 提案，仍须明确确认。反馈和问卷留在 Bridge 的账户私有存储。

动作反馈例 `{"draft_id":"DRAFT_ID","exercise_feedback":{"exercise_index":0,"activation_sites":["上背"],"rir":3,"reduced_difficulty":false,"discomfort":"none","note":"虚构样例"}}`。若明确有不适，使用 `"discomfort":"reported"` 并填 `pain_sites`。省略字段表示未回答。

对已存在的计时目标，可用 `preview_plan_change` 添加 `set_exercise_target` 动作并填写 `seconds`。正式、热身和侧间休息分别使用 `rest_sec`、`warmup_rest_sec`、`side_rest_sec`。再用相应的 `rest_off`、`warmup_rest_off` 或 `side_rest_off` 明确关闭计时，原生 0 或未设置的继承规则保留。

开练后调用原有的 `draft_add_set` 或 `draft_update_set` 保存实绩。每次本地修改使用最新 `revision`，进程重启后调用 `get_workout_draft` 取得同一草稿。时钟结束后使用 `preview_finish_workout_draft` 查看报告与实际写入快照。明确确认后调用 `commit_finished_workout_draft`。若收到 `verification_pending`，先用原恢复工具只读检查。

图表工具返回 `series` 和可保存为 SVG 查看或嵌入的 `svg`。最多 90 天，容量和动作负重分开标注重量口径。没有记录的位置留空；明确记录为零的位置显示在零轴。合成示例：[容量](v050-charts/volume.svg)、[肌群](v050-charts/muscles.svg)、[体重](v050-charts/weight.svg)、[进步](v050-charts/exercise.svg)、[不适](v050-charts/discomfort.svg)。

## 验收及后续操作

在规范化临时路径下运行 `npm test`。本机 Node 24.22.3 实际通过 219 项，含 10 项新增回归。隔离 v1.4.5 用合成账户实际完成 25 组验收。包括官方目录、配对、冲突、响应丢失、重启后续练、官方 MCP 对照和官方 Web 状态模块回读。Web 状态模块运行在测试 DOM 中。另在本机 Chrome 中打开同一隔离服务的官方 Web 界面，查阅训练详情中的两组实测次数及 23 秒计时、同日两次称量及 61 kg 日均值、腰围 76.2 cm。记录及截图均来自虚构账号。Android 和 iOS 实机验收未执行。

GitHub Actions 使用 Node 22，对三个固定上游版本执行隔离 API 验收。通过后构建 linux/amd64 并断网启动容器，检查 MCP 初始化及工具数。发布任务仅在原有 main/tag 触发条件满足时运行。现行流程合并到 main 会触发 main 镜像发布，推送版本标签会触发正式镜像发布。后续单独审批合并时，应先确认是否同时授权该自动发布，或先调整发布触发方式。

正式升级须先确认目标镜像和部署范围，再备份现有 Bridge `store` 及部署配置。使用已发布的固定标签，只重建 Bridge；先以只读模式确认连接、目录、旧草稿和工具，再决定何时启用写入。回滚时恢复上一个固定标签，只重建 Bridge。目录可在 Bridge 停止且确认文件摘要后恢复到刷新前的备份。旧代码能读取原有本地文件，新增计时草稿应先在 v0.5.0 内完成或保留以待复核。镜像回滚不会逆转已确认同步到 openGym 的数据。其恢复应比较最新状态，再按权限和版本单独确认。
