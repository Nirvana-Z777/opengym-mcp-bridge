没有连接 NAS、Cloudflare Tunnel 或生产 openGym；没有读取生产配置、账户、Token、历史数据或私人密钥。测试服务及 Bridge 使用新建临时目录；完成时终止子进程并移除临时凭据及数据。官方源码保留在独立 checkout，没有复制到 Bridge 运行时或镜像。

用于故障注入的本地代理只记录方法、路径、HTTP 状态码和请求次数；转发目标固定为本次新建的官方 API。它在一个场景中丢弃已成功写入的响应，在另一个场景中制造官方并发写入。正常场景使用相同的真实官方 API，不模拟响应内容。

## 实际通过项目

| 验收项目 | 实际结果 |
| --- | --- |
| 新账户及配对 | 新账户初始 state 为 null；官方配对成功，一次性码不可重复兑换；37 个 MCP 工具可用 |
| A/B/C 计划创建 | 三个计划及星期关联在一次预览中创建；预览不写入，缺少确认不写入，确认后仅一次 PUT |
| 已有计划完整动作编辑 | 同一批次改名、增加动作、排序、替换动作、修改目标、删除动作；ID 稳定，未知扩展保留，回读匹配 |
| 备份 | 第一次成功写入前生成真实原始快照，内容与原始 state 相同，文件权限 0600 |
| 备份故障 | 用普通文件阻塞备份目录，真实文件系统失败使提交返回 backup-failed，零 PUT |
| 版本冲突 | 官方客户端修改后旧预览被拒绝，零 Bridge PUT；不覆盖新修改 |
| 提交瞬间竞争 | 最后预检后再制造官方写入，官方返回真实 HTTP 409；一次请求后消费提案，不重试，不覆盖 |
| A/B/C 训练草稿 | 三个计划分别通过精确 routine_id 关联；实际组数从空草稿逐组录入，不把计划目标当作实测值 |
| 持久化和中断恢复 | A 草稿录入后退出并重启 MCP 进程，完整内容和 revision 保持一致 |
| 修改与关联切换 | 修改实测组、备注、A→B→A 关联；均只更新本地草稿，不写官方训练记录 |
| 完成确认 | 完整预览包含 routine_id 和实际组数；错误确认被拒绝，明确确认后单次提交并通过真实回读 |
| 重复提交保护 | 已使用提案不可再次提交；已完成草稿不可再次生成完成提案 |
| 旧草稿预览及取消 | 修改组后旧预览失效；删除组、删除动作、取消草稿只影响本地存储，零 PUT |
| 写入成功但响应丢失 | 官方已保存时主动丢弃响应，草稿保持 verification_pending；重启后只读恢复为 committed，无第二次 PUT |
| 原生记录兼容 | 官方 history helper 能识别 A/B/C routine 归属；A 容量 18、B/C 各 6，与实测组一致 |
| 删除训练及 Undo | 使用官方 stampChange/mergeStates 与真实 API：删除后该周训练由 3 降至 2、容量由 30 降至 12；Undo 后恢复 3/30，动作历史不重复 |
| 删除计划及 Undo | 通过官方客户端原生逻辑删除整个 C 计划后，已有训练保留原 ID；缺失计划不能关联新草稿，Undo 后恢复关联能力 |
| 体重及反馈 | 本地记录重启后可读；官方 state 完全不变，synced_to_opengym 为 false |
| 官方前端同步模块 | 实际 useStore 从真实 API 拉取 Bridge 的 3 个计划和 4 条虚构训练，不额外 PUT；计划修改回写可由 Bridge 读出；删除和 Undo 保留正确记录及扩展字段 |

上表按能力拆分展示；自动化脚本组织为 **15 组检查**，其中 A/B/C 分别独立运行完成流程，前端模块另有一项真实 HTTP 集成测试。Bridge 成功提交 6 次，另有 1 次预期的 409 拒绝；官方客户端初始化、竞争写入、删除及撤销不计入 Bridge PUT 数。

## 未完成项和剩余风险

1. **真实网页浏览器画面未验收。** 已启动官方 Vite 网页服务并尝试浏览器访问 localhost；浏览器与隔离命令环境不共享网络，连接被拒绝。因此没有把模块测试算作网页 UI、轮询间隔、后台恢复、Service Worker/PWA 缓存或完整登录操作通过。
2. **Android 实机未测试。** 未验证 APK 配对、原生存储、前后台切换、断网重连、移动端 UI 或与系统健康平台的同步。happy-dom 和 Node 测试不能替代设备验证。
3. 官方服务以源码运行，没有在本环境运行官方 Docker 镜像；Bridge 镜像构建和离线启动由现有 CI 检查。未测试 ARM/NAS 文件系统、断电或真实设备网络。
4. 兼容性结论限定官方 v1.4.1 的上述提交。未来官方版本、超大数据集、复杂训练格式及多 Bridge 实例并发不在本次验收范围。
5. 整个计划的删除/撤销使用官方客户端原生接口流程验证。Bridge MCP 本次提供的删除操作是计划内动作和本地草稿删除，并没有新增 delete_routine 工具。
6. 体重/反馈是 Bridge 私有记录，不声称已同步到官方网页或 Android。运行时 package 仍标记 0.3.2，正式版本号调整、正式镜像及部署属于后续单独批准的发布步骤。

## 重现与 CI

在一次性开发/CI 环境中检出官方固定提交，分别在 `api/` 执行 `npm ci --omit=optional --ignore-scripts`、在 `frontend/` 执行 `npm ci --ignore-scripts`，然后从 Bridge 根目录运行：

```bash
npm ci --ignore-scripts
npm test
node scripts/acceptance-official.mjs /absolute/path/to/independent/openGym
```

脚本拒绝非固定提交或已修改的官方 tracked 源码，不接受现成服务 URL、账户导出或凭据路径。前端探针临时复制为官方 checkout 内的独立测试文件，测试后删除；测试账户和配对凭据不进入报告。正常完成后移除临时目录。

CI 新增只读权限的 `official-compatibility` job，安装官方锁定依赖后运行相同 15 组验收；`build` 同时依赖完整回归和官方兼容性验收。PR 事件继续跳过发布任务，未放宽任何写入、发布或分支保护条件。查看 [PR #3 checks](https://github.com/Nirvana-Z777/opengym-mcp-bridge/pull/3/checks) 获取最新提交的完整结果。

本次没有修改 main，没有合并 PR，没有创建 Release、发布正式镜像或升级 NAS。
